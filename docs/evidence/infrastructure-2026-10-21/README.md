**Date:** 21 October 2026 · **Task status:** IN PROGRESS  
**Scope:** SEC-06 local foundation; no product redesign or personal-data migration.  
**Hosted acceptance:** pending at the product owner's explicit request.

## Implemented outcome

The existing production web app can now run through a same-origin Fastify BFF with database/Auth readiness checks. Two independent local standard Postgres 17.11/Auth stacks initialize from the committed additive migration. Separate BFF, worker and lifecycle login credentials inherit narrowly scoped non-login roles; each currently reads only the installation marker. The application remains a local personal-data app: no account/session, cloud sync, invitation or remote notification API was added.

The BFF refuses invalid environment/provider/database configuration, a changed installation UUID, an elevated/misgranted runtime role or a reviewer static build. Its static allowlist excludes source, environment files, provenance text, traversal and escaping symlinks. Logs and errors omit credential/request contents. Both web builds reject backend/private imports and unapproved exposed environment variables.

Each local stack has its own signing/API/runtime credentials, Docker network and volumes. Actual published ports are restricted to loopback. The CLI's built-in Postgres development administrator password remains local-only; this configuration is not suitable for public hosting. Protected files and retained volumes are documented in [the environment guide](../../BACKEND-ENVIRONMENTS.md).
